当个人博客接入日常助手：一次最小化验证

最近，我把个人博客接入了日常助手。不过，这次我没有打算展开整个系统的设计，只想验证一个最简单的场景：从首页把一段想法交给流水线，再由 GitHub Actions 写成文章并发布。

为什么先做这个验证

在构建自动化写作流程时，最容易出问题的地方往往是各个环节的衔接。想法如何传递？流水线如何触发？文章如何生成并发布？如果这些基础环节没有跑通，后续再多的功能都是空中楼阁。所以，我决定先聚焦于这个最小闭环，确保从输入到输出的路径是畅通的。

流水线是如何工作的

整个过程可以概括为三个步骤：

  1. 提交想法：在博客首页，我有一个简单的输入框，用来填写文章标题和初步想法。提交后，这些信息会被发送到日常助手的接口。
  2. 触发流水线：日常助手接收到想法后，会将其格式化为一个特定的请求，触发 GitHub Actions 的工作流。这个工作流配置在博客的代码仓库中。
  3. 生成并发布：GitHub Actions 启动后，会运行一个脚本，调用语言模型根据想法生成完整的 Markdown 文章，然后自动提交到仓库并触发部署，最终文章出现在博客上。

这次验证的结果

我提交了一个简单的想法：“个人博客已经接到日常助手。这次只验证从首页把一段想法交给流水线，再由 GitHub Actions 写成文章并发布。” 几分钟后，一篇结构完整的文章就出现在了博客上，标题、摘要和正文都符合预期。

整个过程没有人工干预，从想法到发布完全自动化。这证明基础流水线是可行的，也为后续扩展功能打下了基础。

下一步

虽然这次验证成功了，但还有很多细节需要完善，比如错误处理、内容质量优化、更灵活的触发方式等。不过，那是以后的事了。现在，至少我知道这条路径是通的。

如果你也在构建类似的自动化写作流程，不妨先从最小闭环开始验证，再逐步迭代。
